## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 프로젝트명 | 열화상 비전과 실시간 동적 ROI 기반의 지능형 안전 방재 시스템 |
| 문제 정의 | 배터리 공장에서는 셀 하나의 이상 발열이 주변 셀로 번져 큰 화재로 이어질 수 있어, 눈에 보이기 전 단계의 발열과 가연성·유해 가스를 빨리 찾아내고 작업자를 안전하게 대피시키는 것이 중요하다 |
| 현장 설정 | 배터리 공장 셀 보관·대기 구역 한 곳을 **일반 카메라 + 열화상 카메라**로 한 방향에서 감시 |
| 핵심 기술 | 열화상으로 고온 영역을 찾아 **위험 구역(ROI)을 실시간으로 만들고**, 일반 카메라로 찾은 작업자 위치와 비교한다 |
| 판단 | 정상 · 주의 · 경보 · 대피 4단계 ([02-state-machine](02-state-machine.md)) |
| 시연 환경 | 배터리 공장 축소 모형 (캡톤 히터 = 셀, 사람 피규어 = 작업자). 온도 기준은 실제 셀 기준, 시연은 히터 안전 범위 안에서 축소 재현 |
| OT 흐름 | 위험 감지 → 이벤트 판단 → 안전 알림 ([00-project-guide](00-project-guide.md) 2번) |

## 2. 요구사항 작성 규칙

| 규칙 | 나쁜 예 | 좋은 예 |
|---|---|---|
| **검증할 수 있게** (숫자·관찰 가능한 결과) | 빠르게 경보를 울린다 | 위험 발생 후 3초 이내에 경보를 울려야 한다 |
| **하나에 하나만** | 고온과 가스를 감지하고 대피로를 안내한다 | 각각 별도 REQ로 나눔 |
| **"무엇을"만, "어떻게"는 빼기** | YOLO로 사람을 인식한다 | 사람 피규어를 인식해야 한다 (방법은 [06-system-design](06-system-design.md)에서 정함) |
| **"~해야 한다"로 끝내기** | ~하면 좋겠다 | ~해야 한다 |

**우선순위** — 필수: 없으면 시연이 성립하지 않음 / 권장: 일정이 허락하면 / 선택: 여유가 있을 때
**검증 방법** — 테스트: 04번 TC로 동작 확인 / 측정: 숫자를 재서 기준과 비교 / 검사: 코드·설정·문서를 보고 확인
**OT 범위** — OT 가이드 p.3의 4개 영역: `입력` 입력·센싱 / `모델` 모델·추론 / `HW` 하드웨어·시스템 / `경보` 경보·검증

**번호 규칙:** 요구사항을 삭제해도 **번호는 다시 쓰지 않습니다.** 삭제된 번호는 "삭제됨"으로 남겨 두어, 예전 이슈·커밋에서 그 번호를 찾았을 때 무슨 일이 있었는지 알 수 있게 합니다. 새 요구사항은 마지막 번호 다음부터 붙입니다.
