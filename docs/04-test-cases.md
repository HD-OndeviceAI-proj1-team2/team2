# 04. 테스트 시나리오·결과서

> **이 문서의 역할**
> "이런 조건을 만들면 → 이렇게 동작해야 한다"를 미리 적어 두고, 실제로 해 본 결과를 기록합니다.
> 요구사항(01)이 모두 검증됐는지, FMEA(05)의 대책이 실제로 동작하는지를 이 문서에서 확인합니다.
>
> - 문서 버전: v0.3 (예시 초안)
> - 담당: 통합·문서 (테스트 실행은 기능 담당과 같이)
> - 관련 문서: [01-requirements](01-requirements.md) · [02-state-machine](02-state-machine.md) · [03-interface](03-interface.md) · [05-fmea](05-fmea.md)

## 1. 이 문서 쓰는 법

1. **왼쪽 칸(사전 조건·절차·기대 결과)은 개발 전에** 씁니다. 개발자는 "무엇을 통과해야 하는지" 알고 만듭니다.
2. **오른쪽 칸(실제 결과·판정)은 테스트할 때마다** 채웁니다. 실제 결과에는 **CSV 로그 폴더 이름**을 꼭 적습니다.
3. 기대 결과는 **숫자와 눈으로 확인할 수 있는 것**으로만 씁니다. ("잘 울린다" ✗ → "3초 안에 부저 0.2초 주기" ✓)
4. 기준값을 바꾸거나 코드를 크게 고친 뒤에는 **전체를 다시 돌립니다** (회귀 테스트).

판정 표기: ✅ 통과 · ❌ 실패 · ⏸ 보류(장비 문제 등) · 빈칸 = 아직 안 함

## 2. 요구사항

요구사항(REQ) 목록과 내용은 [01-requirements](01-requirements.md)에 있습니다. 이 문서의 '검증' 칸은 그 번호를 가리킵니다.

## 3. 기준값 기호

테스트 표에서는 숫자 대신 아래 기호를 씁니다. **실제 숫자는 [`config/thresholds.csv`](../config/thresholds.csv) 한 곳에서만 관리**하고, 아래 표는 그 파일의 요약입니다. 기준값이 바뀌어도 테스트 표를 고칠 필요가 없게 하기 위해서입니다.

| 기호 | 뜻 | 값 | 정한 근거 |
|---|---|---|---|
| `T_HOT` | 고온 기준 온도 | ( )℃ | 히터 실측 후 |
| `T_EXTREME` | 대피 기준 온도 | 100℃ | ADR-0001 |
| `EXTREME_HOLD_SEC` | `T_EXTREME` 유지 시간 | 5초 | 02 그림 |
| `RELEASE_HOLD_SEC` | 주의→정상 해제 유지 시간 | 20초 | 02 그림 |
| `HOLD_SEC` | 고온 지속 판단 시간 | 10초 | 02 그림 |
| `RATE_HOT` | 급상승 기준 | ( )℃/초 | |
| `GAS_RATIO` | 가스 경보 기준 배수 | ( )배 | |
| `FAULT_SEC` | 센서 응답 없음 판단 시간 | ( )초 | |
