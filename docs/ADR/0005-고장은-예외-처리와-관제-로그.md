# ADR-0005: 고장은 단계로 만들지 않고, 예외 처리 + 관제 센터 로그로 다룬다

- 상태: 확정 (2026-11-25 팀 결정)
- 바꾸는 결정: 02-state-machine v0.4까지의 "고장 표시(파랑 LED + 고장 부저 패턴)"

## 배경
카메라·센서가 데이터를 주지 않는 상황(케이블 빠짐, 프레임 멈춤, 읽기 오류)을 처음에는 현장에 파랑 LED와 부저 패턴으로 알리기로 했다. 하지만 단계 표시(초록·노랑·빨강)와 고장 표시가 같은 LED·부저를 나눠 쓰면 작업자가 헷갈릴 수 있고, 고장은 작업자가 아니라 **관리자가 고쳐야 하는 일**이다.

## 결정
- 고장은 **경보 단계가 아니다.** 단계를 올리거나 내리지 않는다.
- 데이터가 `FAULT_SEC` 이상 오지 않거나 읽기 오류가 나면 **예외 처리**한다: 프로그램은 멈추지 않고, 그 센서 값은 `None`으로 두고 나머지 센서로 판단을 계속한다.
- 고장이 생기면 **관제 센터에 고장 로그**(어느 센서, 언제, 오류 내용)를 보내고 DB에 기록한다. 복구되면 복구 로그를 보낸다.
- 주의·경보·대피 단계가 될 때도 관제 센터에 **사유와 당시 데이터 로그**(온도, 가스, 위험 구역, 작업자 위치, 안내 출구, 스냅샷)를 보낸다. 항목은 [03-interface](../03-interface.md) 5-1번.

## 결과
- 좋은 점: 현장 LED·부저는 위험 단계만 뜻하게 되어 작업자가 헷갈리지 않는다. 관리자는 관제 센터에서 원인과 데이터를 함께 보고 판단할 수 있다.
- 주의할 점: 현장에서는 고장을 알 수 없다. **관제 센터를 아무도 보지 않으면 고장이 계속 모르게 남을 수 있다** (예: 열화상이 멈추면 고온을 놓침 — FMEA F-01). 관제 센터 화면에서 고장 로그가 눈에 띄게 보이도록 만든다.
